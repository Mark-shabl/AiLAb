# Инструкция по работе с AI Lab

Краткий пошаговый гайд: от первого запуска до дообучения, мониторинга и чата с моделью.

---

## 1. Подготовка (один раз)

1. Установите [Docker Desktop](https://docs.docker.com/get-docker/) (Windows/macOS) или Docker Engine + Compose (Linux).
2. Склонируйте репозиторий и перейдите в каталог проекта.
3. Создайте файл окружения:
   ```powershell
   copy .env.example .env
   ```
4. Откройте `.env` и при необходимости укажите **`HF_TOKEN`** ([токен Hugging Face](https://huggingface.co/settings/tokens)) — нужен для моделей с ограниченным доступом (например, Llama).

---

## 2. Запуск лабы

### Вариант A — есть NVIDIA GPU и Docker видит GPU

Из корня проекта:

```powershell
docker compose --env-file .env up -d
```

Или явно:

```powershell
docker compose -f gpu/docker-compose.yml --env-file .env up -d
```

### Вариант B — только процессор (как на многих ПК с Docker Desktop без GPU в WSL)

```powershell
docker compose -f cpu/docker-compose.yml --env-file .env up -d
```

**Важно:** не поднимайте оба стека одновременно на одной машине — порты совпадают.

### Пересборка TensorBoard (редко нужно)

```powershell
docker compose -f cpu/docker-compose.yml --env-file .env up -d --build
```

### Остановка

```powershell
docker compose -f cpu/docker-compose.yml --env-file .env down
```

(или без `-f cpu/...`, если запускали GPU-стек с корня.)

## 4. Куда класть файлы на диске

Все постоянные данные — в папке **`data`** рядом с проектом:

| Папка | Назначение |
|--------|------------|
| `data/datasets/` | Обучающие датасеты (JSON и др.) |
| `data/models/` | Локальные модели или скачанные веса |
| `data/output/` | Чекпоинты и результаты обучения |
| `data/hf_cache/` | Кэш Hugging Face |
| `data/logs/tb/` | Логи TensorBoard |
| `data/logs/aim/` | Репозиторий Aim |
| `data/notebooks/` | Ваши Jupyter-ноутбуки |

Внутри контейнера LLaMA-Factory **`/app/output`** соответствует **`data/output`** на хосте, **`/app/data`** — **`data/datasets`**.

---

## 5. Типичный сценарий: дообучение через веб-интерфейс

1. Положите датасет в `data/datasets/` (форматы, которые поддерживает LLaMA-Factory: Alpaca, ShareGPT, ChatML — см. документацию проекта).
2. Откройте http://localhost:7860.
3. Выберите модель (ID с Hugging Face или путь к локальным файлам в `/app/models` → у вас это `data/models`).
4. Перейдите к дообучению (**Fine-tune**), выберите метод (для больших моделей на одной видеокарте обычно **QLoRA**).
5. В расширенных настройках укажите:
   - **`report_to: tensorboard`** — чтобы метрики попадали в TensorBoard;
   - **`output_dir: /app/output`** — чтобы чекпоинты сохранялись в `data/output`.
6. Запустите обучение.
7. Параллельно откройте http://localhost:6006 — смотрите loss, learning rate и при наличии логов — гистограммы.

Если **:7860 не открывается**, убедитесь, что в `docker-compose` для сервиса `llama-factory` задано **`command: llamafactory-cli webui`**, затем:

```powershell
docker compose -f cpu/docker-compose.yml --env-file .env up -d --force-recreate llama-factory
```

## 6. Jupyter: свой код и гистограммы слоёв

1. Откройте http://localhost:8888.
2. В каталоге **`work`** откройте `01_custom_training.ipynb` (это файл из `data/notebooks/`).
3. Установите в ноутбуке зависимости из первой ячейки при необходимости.
4. Скрипты **`layer_histograms.py`** и **`aim_logger.py`** смонтированы в `/home/jovyan/scripts` — их можно импортировать для логирования весов/градиентов и в Aim.

Для «тяжёлых» моделей CPU-стек будет очень медленным; для экспериментов лучше GPU.

## 7. Aim

- После первого запуска каталог `data/logs/aim` инициализируется автоматически при старте контейнера.
- Если обучение шло только через LLaMA-Factory с TensorBoard, метрики в Aim можно подтянуть скриптом **`tb_to_aim`** из `scripts/aim_logger.py` (пример в ноутбуке).

---

## 8. Инференс: Ollama (после обучения)

Обучение и Ollama разнесены по профилю **`inference`**, чтобы не конкурировать за GPU.

Поднять только Ollama (пример для CPU-стека):

```powershell
docker compose -f cpu/docker-compose.yml --env-file .env --profile inference up -d ollama
```

Модель для Ollama обычно в формате **GGUF**; том `data/models` в контейнере доступен как **`/models`**. Создание модели в Ollama — см. основной **README.md** (пример с `Modelfile` и `ollama create`).

## 11. Если что-то пошло не так

- **GPU не виден в WSL / Docker Desktop** — используйте CPU-стек или настройте GPU по документации NVIDIA и Docker.
- **Порты заняты** — измените значения в `.env` (`LF_PORT_UI`, `JUPYTER_PORT` и т.д.).
- **Aim крутит перезапуск** — обновите compose (должны быть `aim init --yes --skip-if-exists` и `aim up`) и выполните `up -d --force-recreate aim`.

Больше ссылок и нюансов — в файле **README.md**.
